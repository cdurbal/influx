# RUA-04 — `test(e2e): the synthetic acceptance data set`
Grille `testeur`. Skill : `test-strategy`.
**Lire :** fiche ; Lectures, ligne 04 ; `R05` §4 ; `modele-archi.md` §5 ; `grep` des données d'exemple dans
`docs/audit-ux-ui/prototypes/proto-*.html` (Maison Azur, « Routine éclat d'hiver », 93JMS4, 7K3MQA).
**Livrer :** `apps/web/e2e/fixtures/recette/` (données typées par espace : marque, créateur, backoffice) et
`apps/web/e2e/support/recette.ts` (chargeurs qui n'appellent que les helpers existants : `seedMember`,
`signedInBrand`, `seedSearchableCreators`, `seedCreatorWithVisuals`, `campaign-states`, `verification-cycle`) ; liste
`NON_RECETTABLE` : état, donnée manquante, décision (`R06b` §5, RU-21, RU-22) ; e-mails `example.test` ; unité
`apps/web/tests/recette-data.test.ts` : aucun montant côté créateur, ni e-mail ni téléphone d'une autre partie,
aucune donnée réelle, chaque état d'une maquette est créable ou dans `NON_RECETTABLE`.
**Ne pas toucher :** API, base (SQL direct hors `support/database.ts`), `staging` ; noms d'utilisateurs réels.
**Prouver :** RUA-T7 ; le chargeur de chaque espace exercé, en 2 cas e2e au plus (≤ 5 s au total, plancher) ; `pnpm check:fast` ;
`pnpm --filter @influx/web exec playwright test <spec> --reporter=line`.
**Arrêt si :** un état exige une écriture d'API absente et non listée dans `R06b` §5.
