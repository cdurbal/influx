# L3A-A — F3 : codes du journal servis par l'export « mes données »
Arbitrage `expert-cybersecurite` (stockage : grille `expert-database`), 2026-11-13. Exécuté par
L3A-07 (`0302`).

## Règle
- **Exporté par défaut** (art. 15) : code et date, un agent vu « INFLUX », ni charge utile ni
  hachage (`0245` l. 730). Les lectures privilégiées (`history.*_read`, `accounts.searched_partial`,
  `queue.entry_opened`, `queue.*_read`, `verification.evidence_viewed`) sont dues (CJUE C-579/21).
- **Exclu seulement** un code dont la survenue révèle :
  - `excluded_security` : une mesure de sécurité interne (détection, signal de fraude, garde
    déclenchée) ; la restituer dirait à qui tient le compte, ou sa boîte, quel geste a déclenché quoi ;
  - `excluded_third_party` : l'acte ou la donnée d'un tiers (art. 15(4)).
- Ni la gravité (`account.deleted`, `critical`, est exporté) ni le caractère interne d'une procédure
  connue de l'intéressé (`agent.break_glass_login`, `dual_control.*`) n'excluent. Un fait annoncé au
  membre (e-mail `auth.new_device`, `verification.rejected`) est exporté.

## Stockage
- `audit.event_types.export_class text not null`, **sans défaut**,
  `check (export_class in ('exported','excluded_security','excluded_third_party'))`.
- `0302` : colonne ajoutée nullable, les 135 codes classés, `set not null`, assertion de fin
  (5 exclus, 130 exportés).
- `activity_log` (`0245` l. 731-741) : jointure sur `audit.event_types`, `export_class = 'exported'` ;
  périmètre acteur ou sujet et autres sections inchangés.
- I-4 : `grant select (code, export_class) on audit.event_types to influx_privacy_definer` et sa
  politique `for select` (aucun droit aujourd'hui).
- **Migration qui ajoute un code** : nomme `export_class` (l'omission échoue, même sous
  `on conflict do nothing`, le `not null` étant contrôlé avant l'arbitrage) ; une exclusion
  s'inscrit au tableau ci-dessous, motif compris, et dans le cas en base ; un reclassement est un
  `update` relu par `expert-cybersecurite`.

## Portée
- Preuve, pile locale à `0301` : `count(*)` de `audit.event_types` = 135 = 5 + 130, aucun code de la
  liste absent de la base.
- Les quatre premiers ont un compte interne pour sujet, le cinquième une demande dont l'agent est
  l'acteur : **aucune ligne servie aujourd'hui ne change**. Le filtre ferme la porte aux codes à
  venir (blocage, signalement) et à tout élargissement du périmètre. Cas en base (L3A-07) : une ligne
  d'un code exclu dont le membre est sujet n'est pas servie ; une ligne exportée l'est toujours.
- Notice inchangée en L3A (rien de dû n'est retenu à un membre) ; le premier code exclu servable à
  un membre ajoute les signaux internes de sécurité à la phrase `excluded` (FR, EN), même jalon.
- `16` l. 1137 (journal conservé après effacement) : sans conflit. Fondement des exclusions de
  sécurité (art. 23 ; DPA 2018, annexe 2 §2) : à confirmer par `expert-conformite-rgpd` au Lot 6.
