## 1. Points de rupture (RU-03) — ligne 02
- `--breakpoint-form: 640px` dans `@theme static` de `TS`, en px comme ses voisins. *M.* rôle (formulaires) ; Tailwind trie par valeur les `--breakpoint-*` de même unité : `form:` entre `sm:` et `md:`, `max-form:` offert ; jamais sous KEO (G3i a). *G.* G3e (ajout permis).
- `@custom-variant bo-wide { @media (width >= 1536px) { @slot; } }` dans `BO`, **avant** `bo-small`. *M.* l'échelle `--breakpoint-*` reste une liste, dans `TS` (CA22) ; forme de `bo-small` ; G3f. Les `@custom-variant` sortent après les points de rupture, dans l'ordre du fichier : `bo-wide:` suit `2xl:`, `bo-small:` l'emporte dans une fenêtre large et basse. Vérifié le 2026-11-25 (`compile` de `tailwindcss` 4.3.3).
- *G.* ligne 02, Vitest du backoffice : même `compile` sur le `globals.css` réel et des candidats synthétiques, ordre attendu (la feuille construite n'a pas ces variantes, aucun écran ne les emploie). Négatifs : troisième variante, variante hors `BO`, ordre inversé.

## 4. Effets sur photo (RU-04) — ligne 01
| Token | `@theme static` (`TS`) | Bloc KEO |
|---|---|---|
| `--effect-photo-scrim-strong` · `-scrim` · `-scrim-soft` | `transparent` | `color-mix(in srgb, var(--color-surface-page) N%, transparent)`, N = 82 · 75 · 45 |
| `--effect-photo-shadow` | `none` | `drop-shadow(0 1px 2px color-mix(in srgb, #000000 50%, transparent))` |

- *M.* `color-mix`, pas de littéral : le bloc KEO n'admet que l'opaque ou cette borne (`02` §21.3 points 2, 3), l'invariant 4 refuse `rgba(…, 0.5)`. Valorisé dans le bloc, où `surface-page` est redéfinie (piège des alias) ; neutre dans le calque thème, comme `--effect-action-glow` (un `:root` non classé battrait le bloc KEO du backoffice). Noir des ombres de la vitrine : aucune couleur nouvelle, jamais un `--color-*`.
- Lecture : `bg-(--effect-photo-scrim…)` → `background-color: var()`, `filter-(--effect-photo-shadow)` → `filter: var()` (compilation vérifiée). `none` neutre : `filter-(…)` ne compose aucune liste (à l'inverse de `box-shadow`), sans contexte d'empilement. Aucun autre filtre sur le même élément (`effect-media-hover` va sur le visuel). Lecteurs : modules de `PHOTO_EFFECT_READERS` (`charter-data.ts`, vide en RUA, rempli par l'écran qui l'emploie).
- *G.* G3i étendue (TD1) : `ColorMixAllowance` reçoit `base` (`var(--color-brand-primary)` par défaut, `var(--color-surface-page)`, `#000000`) et `percent` exact (`maxPercent` du halo inchangé) ; `KEO_COLOR_MIX` gagne les quatre tokens ; bloc KEO seul. Négatifs : voile en vert, à 80 %, valorisé dans `@theme` ; `surface-page` dans le halo du bouton ; `--color-*` listé ; resserrement : `rgba(`, `hsla(`, `#rrggbbaa` dans un `--effect-*`. G3c : noms dans `@theme`. G8 : lecteur hors `PHOTO_EFFECT_READERS`.
- *G.* G3d : `withGlowPeak` devient `withMixOver(tokens, token, ground, name)`, une fonction pour deux usages : halo sur `surface-page`, voile sur `PHOTO_WORST` = `#ffffff` (photo blanche, pire cas d'un texte clair), pourcentage lu dans la feuille. `PHOTO_SCRIM_PAIRS`, à part comme `GLOW_PEAK_PAIRS` : `text-primary` × voiles 82 et 75 % ≥ 4,5:1 (11,01 · 8,46). 45 % : décor, sans texte, sans paire.
