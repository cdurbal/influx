# PL-04a — `fix(db): refuse non-string country bases in the Apollo sync settings`

Grille `expert-database`. Skill : `supabase-schema`. Ajoutée par l'arrêt de PL-04 (choix A du
fondateur, 2026-10-31) : exception à l'invariant 1 et seule migration du jalon.

**Lire :** `supabase/migrations/0141_leads_apollo_excluded_countries.sql` (contrainte
`sync_settings_value_shape`) ; `apps/api/src/domains/leads/connectors/apollo/qualification.ts`
(`unreadableApolloKeys`) ; `05` RG160 et RG162 (`Grep`) ; le fichier `db-tests` qui couvre déjà
`apollo_legal_basis` (`Grep`).

**Constat (PL-04) :** `apollo_legal_basis.by_country` accepte `1`, `true`, `{}`, `[]`, `1.5`, `[1]`
(seul `null` est refusé, 23514). En mode lax, `@.value != "consentement_requis"` entre un non-texte
et un texte vaut « inconnu » : le filtre ne trouve rien, `not jsonb_path_exists` laisse passer. Le
worker refuse ensuite ces valeurs (zod `z.enum`) : chaque ligne Apollo échoue (RG160) et il ne
démarre plus (RG162).

**Livrer :**
- Migration `0151_leads_apollo_basis_string_values.sql` (SQL relu, aucune autre table) : la
  contrainte refuse toute valeur de `by_country` qui n'est pas une des chaînes admises (par exemple
  `@.value.type() != "string"` en plus, ou un chemin `strict`) ; mêmes SQLSTATE qu'aujourd'hui ;
  tout le reste de la contrainte inchangé, mot pour mot.
- Avant d'écrire : lecture seule de `leads.sync_settings` sur `staging` (D70, `.env.local`,
  aucune valeur recopiée) ; une ligne qui violerait la nouvelle contrainte : arrêt.
- Cas ajoutés au fichier `db-tests` existant : les six valeurs ci-dessus refusées ; plancher relevé.

**Ne pas toucher :** le travail non commité de PL-04 dans l'arbre (`db-tests/tm1-apollo-settings-parity.test.ts`
et les titres J9T-8 de `t8-verify-code`, `t8-reauth-email-change`, `t13-error-responses`,
`leads-drain`, `config`, `signup-form`) : ni modifié ni indexé. `qualification.ts` inchangé. Aucun
`railway up` : la migration part par la CI (`CLAUDE.md` §7 règle 4).

**Prouver :** **toute la suite base** (migration) ; `tm1-apollo-settings-parity.test.ts` (présent
dans l'arbre) 49 sur 49 ; `pnpm check:fast`. Fichier seul pendant le codage :
`pnpm exec vitest run --project db <fichier> --reporter=dot` depuis `apps/api` (le filtre de
`test:db` est cassé jusqu'à PL-04b).

**Arrêt si :** la donnée de `staging` viole la nouvelle contrainte ; resserrer exige de toucher une
autre clé que `apollo_legal_basis` ou la fonction `unreadableApolloKeys`.
